---
name: Intake page double header
description: Why the /intake/:slug SSR page must request the web-form embed with ?chrome=0
---

The public intake page `/intake/:slug` (SSR, `routes/public-sites.ts`) renders its own
prominent header (eyebrow + headline + subhead + trust banner) above the form card. The
modern web-form embed (`/api/web-forms/:tortId/embed.js`, generated by
`generateWebFormEmbed`) ALSO renders `introHeadline`/`introSubhead` at the top of the
form. Loaded together this prints the title + description twice.

**Rule:** any surface that wraps the web-form embed in its own chrome/header must load the
embed with `?chrome=0` (which sets `showHeader=false`, omitting introHeadline/introSubhead).
Standalone third-party embeds omit the param and keep their header so they have a title on
the host page.

**Why:** the embed is dual-use (MTOS-hosted intake page + partner landing pages). The
header belongs to exactly one of them at a time; the wrapping page decides via the query
param, not the embed.

**How to apply:** if you add another page that embeds a web form and gives it its own
title, append `?chrome=0` to the embed src. If you change the embed's internal header
markup, this duplication can silently come back on any wrapper that doesn't pass chrome=0.
