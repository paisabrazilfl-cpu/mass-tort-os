# Dev preview serves the built CRM, shadowing Vite dev

The Replit dev preview ("/") does NOT show live Vite/HMR output for the CRM. Source
edits to `artifacts/mtos-crm/src/**` do not appear in the preview until the CRM is
rebuilt.

**Why:** the api-server's `artifact.toml` `[[services]]` claims `paths = ["/api",
"/intake", "/c", "/glossary", "/how-it-works", "/sitemap.xml", "/robots.txt", "/"]`
— including bare `/`. So the proxy routes `/` to the **api-server** (Express),
which serves the pre-built SPA from `artifacts/mtos-crm/dist/public` with an SPA
fallback (`app.ts` static block). The `artifacts/mtos-crm: web` Vite dev server
(port 24540) genuinely has the latest code, but it is shadowed for `/` and never
reached by the browser. `dist/public` is gitignored and only regenerated by a
build, so it goes stale the moment you edit source.

Symptoms when this bites: a brand-new nav item / page / copy change is invisible in
the preview AND in Playwright tests, even though the source is correct, typecheck
passes, and `curl localhost:24540/` (Vite directly) shows the edit. Tell-tale:
`curl localhost:80/` returns an `index.html` referencing a hashed
`/assets/index-*.js` (a build) instead of `/src/main.tsx` (Vite dev).

**How to apply / fix for verification:** rebuild then restart the api-server:
`pnpm --filter @workspace/mtos-crm run build` then restart `artifacts/api-server: API Server`.
express.static serves the new files; the no-cache index.html picks up the new hash.
Production (Render) is unaffected — it always rebuilds, so source-only pushes deploy fine.

**Proper (unapplied) fix, needs user sign-off:** remove `/` from the api-server
artifact's `paths` (via the artifacts skill) so `/` routes to the CRM Vite dev
server and HMR works live. Production serving is unchanged (Render runs the bundled
api-server which serves `/` in-process, not via these dev-proxy paths).
